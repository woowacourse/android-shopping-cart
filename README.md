- [ ] 기존 StateHolder 방식을 ViewModel + UiState 구조로 전환
- [ ] 상품 목록(더보기)과 장바구니의 페이징 처리 로직을 전담하는 객체 분리
- [ ] 불필요한 패키지 및 의존성 제거

## 🎯 기능 목록

### 아키텍처 및 공통 상태 관리
- [ ] 프로세스 종료 시 상태 복구 (State Preservation)
  - 시스템에 의해 앱 프로세스가 종료되더라도, 사용자가 선택 중이던 '현재 수량 상태'가 초기화되지 않고 유지되도록 처리
- [ ] 단방향 데이터 흐름(UDF) 적용 유지
  - 수량 변경 등 모든 상태 변화와 이벤트가 한 방향으로 흐르도록 상태 관리 구조(State Holder 등) 고도화
- [ ] 공통 컴포넌트 재사용
  - 상품 수량을 증감시키는 UI(+, - 버튼과 수량 텍스트)를 독립적인 공통 컴포저블(Component)로 분리하여 다양한 화면에서 재활용

### 도메인 및 데이터 계층
- [ ] 장바구니 내 특정 상품의 수량을 증감하거나, 수량이 0이 될 경우 목록에서 제거하는 비즈니스 로직 및 레포지토리 연동 구현

### UI 및 프레젠테이션 계층
- [ ] 상품 목록 화면 (B마트 UX 적용)
  - [ ] 장바구니에 담기지 않은 상품은 썸네일 우측 하단에 `+` 플로팅 버튼 노출
  - [ ] `+` 버튼 클릭 시 장바구니에 상품이 담김과 동시에, 버튼 영역이 '수량 조절 UI(-, 현재 수량, +)'로 즉시 전환
  - [ ] 목록에서 수량을 조절하면 장바구니 데이터(전역 상태)에 실시간으로 반영
- [ ] 장바구니 화면 연동
  - [ ] 장바구니 화면에서 특정 상품의 수량을 변경하거나 삭제하면, 상품 목록 화면의 수량 상태 UI에도 즉시 동기화되어 반영
- [ ] 상품 상세 화면
  - [ ] 상품 상세 화면 내에서 장바구니에 담을 상품의 수를 조절할 수 있는 공통 수량 선택 UI 적용
  - [ ] 선택한 수량만큼 장바구니에 정확히 담기거나 업데이트되도록 이벤트 연동

## 🧪 테스트 명세

### 비즈니스 로직 및 상태 테스트
- 수량 관리 로직
  - [ ] 수량을 1 증가시키면 장바구니의 해당 상품 수량 데이터가 정확히 1 증가한다.
  - [ ] 수량이 1일 때 빼기(-) 버튼을 누르면 장바구니에서 해당 상품이 올바르게 삭제된다.
- 상태 보존(Save/Restore) 테스트
  - [ ] 화면 회전이나 시스템에 의한 프로세스 종료(Process Death) 후 앱을 재시작했을 때, 조작 중이던 수량 상태가 초기화되지 않고 정상적으로 복구된다.
- 상태 동기화 테스트
  - [ ] 장바구니 레포지토리의 수량 상태가 변경되었을 때, 이를 관찰하고 있는 UI(상품 목록, 상품 상세)의 상태도 누락 없이 갱신된다.
