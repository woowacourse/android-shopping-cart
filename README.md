## 상품 목록 화면

- 상품 카드에 + 버튼이 있다.
    - \+ 버튼을 눌렀을 경우 장바구니에 상품을 추가한다.
    - 장바구니의 상품의 개수를 \- 버튼과 \+ 버튼으로 조절할 수 있다.
    - 상품이 한 개일 때 \- 버튼을 누르면 장바구니에서 상품을 제거하고 \+ 버튼으로 UI가 돌아간다.
- 장바구니에 동일한 상품이 이미 존재한다면, 버튼 UI가 나타나야 한다.
- 각 상품이 장바구니에 몇 개가 담겨있는지 알고 있어야 한다.

## 기능 요구 사항

- 상품 목록에서 장바구니에 담을 상품의 수를 선택 할 수 있다. (B마트 UX 참고)
- \+ 버튼을 누르면 장바구니에 상품이 추가됨과 동시에 수량 선택 버튼이 노출된다.
  - 상품 목록의 상품 수가 변화하면 장바구니에도 반영되어야 한다.
  - 장바구니의 상품 수가 변화하면 상품 목록에도 반영되어야 한다.
- 상품 상세에서 장바구니에 담을 상품의 수를 선택할 수 있다.

## 프로그래밍 요구 사항

- 반복되는 컴포넌트(상품 수량 선택)를 재활용할 수 있는 방법을 고민해본다.
- 단방향 데이터 흐름(UDF)을 적용한다.
- 시스템에 의한 프로세스 종료 시에도 현재 수량 상태가 유지되도록 처리한다.

## 변경되어야 할 도메인

### 상품

- 상품의 id를 비교하는 행동이 있어야 한다.

### 장바구니 상품

- 개수라는 상태가 추가되어야 한다.
- 상품의 개수를 추가 및 삭제하는 행동이 있어야 한다.
- 상품의 개수와 상품의 가격으로 얼마인지 알려주는 행동이 있어야 한다.
- 상품이 장바구니에 존재하는지 확인하는 행동이 있어야 한다.
  - 상품 목록 화면에서 상품을 클릭했을 때 장바구니에 이미 존재하는 상품이라면 상품 상세 화면에서 해당 상품의 개수를 가져와야 한다.
  - 상품 목록 화면에서 상품 카드를 그릴 때 장바구니에 존재하는 상품 카드 UI에 장바구니에 들어간 해당 상품의 개수를 나타내야 한다.

### 장바구니(Cart)

- 장바구니에 총 몇 개의 상품이 존재하는지 알 수 있어야 한다.

## Room 연결

### 장바구니

- 종료되지 않아야 하는 데이터 -> 장바구니 목록
- 장바구니 목록에는 어떤 값이 있을까?
  - productId
  - quantity
- productId를 사용하여 특정 상품을 불러올 수 있다.
- 불러온 특정 상품의 개수는 quantity가 값을 가지고 있다.

### 최근 본 상품

- 종료되지 않아야 하는 데이터 -> 최근 본 상품 목록
- 최근 본 상품 목록에는 어떤 값이 있을까?
  - productId
- productId를 사용하여 특정 상품을 불러올 수 있다.
- 최근 본 상품 목록은 10개까지만 소유하고 있어야한다.
  - 어떻게? 리스트의 길이가 10을 넘으면 맨 앞의 값을 삭제하고, 뒤에 새로운 값을 넣기?
