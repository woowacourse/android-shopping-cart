# Android Shopping Cart

## 1단계 구현 내용 정리

- [x] `Product`가 고유 ID, 이미지, 이름, 가격을 가지도록 구현했다.
- [x] `Cart`가 장바구니 상품 목록을 추가하고 삭제할 수 있도록 구현했다.
- [x] `ProductWithQuantity`를 도입해 상품과 수량을 함께 다룰 수 있도록 구현했다.
- [x] `Price`가 0보다 커야 한다는 도메인 제약을 적용했다.
- [x] 상품 목록, 상품 상세, 장바구니의 기본 화면 흐름을 구성했다.

## 2단계 구현 내용 정리

- [x] 상품 목록 화면에서 더보기 버튼을 눌러 상품을 20개씩 추가로 노출할 수 있도록 구현했다.
- [x] 장바구니 화면에서 상품 개수에 따라 페이지네이션이 노출되도록 구현했다.
- [x] 첫 페이지와 마지막 페이지 여부에 따라 좌우 이동 버튼의 활성/비활성 상태를 처리했다.
- [x] 페이지 계산, 마지막 페이지 판단 같은 파생 로직을 상태 객체 또는 ViewModel 쪽으로 정리했다.

## 3단계 구현 내용 정리

- [x] 상품 목록 화면에서 장바구니에 담을 수량을 직접 조절할 수 있도록 구현했다.
- [x] 상품 상세 화면에서도 장바구니에 담을 수량을 선택할 수 있도록 구현했다.
- [x] 상품 목록에서 변경한 수량이 장바구니에 반영되도록 구현했다.
- [x] 장바구니에서 변경한 수량이 상품 목록에도 반영되도록 구현했다.
- [x] 반복되는 수량 선택 UI를 재사용 가능한 컴포넌트로 분리했다.
- [x] `ViewModel`, `Repository`, `Room`을 도입해 상태를 화면 밖으로 분리하고 저장 가능한 구조로 개선했다.
- [x] `Flow`를 사용해 상품 목록과 장바구니가 같은 상태를 관찰하도록 수정했다.

## 프로그래밍 요구사항

- [x] 반복되는 상품 수량 선택 UI는 재사용 가능한 컴포넌트로 분리한다.
- [ ] 단방향 데이터 흐름(UDF)을 적용하여 상태 소유와 이벤트 흐름을 명확히 한다.
- [x] 시스템에 의해 프로세스가 종료되더라도 현재 수량 상태를 복원할 수 있도록 처리한다.

## 4단계 기능 구현 목록

### 기능 요구 사항
- [ ] 최근 본 상품이 있는 경우 상품 목록 상단에서 최대 10개까지 확인할 수 있다.
- [ ] 마지막으로 본 상품 1개를 상품 상세 페이지에서 확인할 수 있다.
- [ ] 마지막으로 본 상품을 선택했을 때는 마지막으로 본 상품이 보이지 않는다.
- [ ] 마지막으로 본 상품 페이지에서 뒤로 가기를 하면 상품 목록으로 이동한다.
- [ ] 앱이 재시작돼도 최근 본 상품 목록과 장바구니 데이터는 유지돼야 한다.


### 프로그래밍 요구 사항
- [ ] 로컬 데이터 유지를 위해 Room을 사용한다.
- [ ] 상품 목록의 HTTP Client를 구현한다.
- [ ] MockWebServer를 사용하여 테스트 환경을 만든다.
- [ ] 네트워크 상태 변경 시스템 이벤트를 감지하여 UI에 반영한다.
